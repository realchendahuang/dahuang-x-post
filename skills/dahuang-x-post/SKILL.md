# Dahuang X Post

把素材重排成能在 X 信息流里被快速理解和转发的内容。优化传播结构，不制造事实，不承诺流量。

## 先判任务

只选一个主任务：

- **改写**：把现有素材写成可直接发布的帖子。
- **Thread**：把有多个独立观点、步骤或证据链的长内容拆开。
- **诊断**：判断当前稿件卡在 Hook、信息密度、可信度还是讨论空间。
- **局部优化**：只改开头、结构、收尾或某一段。

用户说“只要一条”“只改开头”“先诊断”时严格收窄，不额外交付整套版本。

## 划清事实边界

改写前提取并保护：

- 人名、产品名、数字、日期、链接、引用和结论。
- 用户已经给出的经历、结果和立场。
- 不确定、缺失或不能公开的信息。

不得补写用户没有提供的收入、用户反馈、Star、阅读量、增长结果、截图、案例或背书。缺链接就不加链接；没有自然互动点就不硬造提问。

## 工作流

### 1. 找出真正值得发的判断

用一句话回答：

- 这条内容最想让谁停下来？
- 素材里最硬、最具体的判断是什么？
- 读者看完能多知道什么？

先重排信息，再润色句子。删除不影响理解的背景、自我介绍和发布仪式感。

### 2. 选择形态

- 一个判断加一个证据：写短帖。
- 三个以上能独立成立的观点、步骤或故事转折：写 Thread。
- 只有零散信息、没有可验证的判断：先给诊断或请用户补一项关键事实，不硬写“爆帖”。

### 3. 选择传播角度

按素材选角度，不固定套模板：

- 直给判断
- 具体结果
- 反常识
- 精准读者
- 失败或踩坑
- 故事瞬间
- 工具或项目价值

默认给 3 个完整版本，但三版必须在判断、证据取舍和节奏上真正不同。素材只支持一个诚实角度时，只给一版，避免伪造差异。

### 4. 写成信息流结构

- 第一屏先给判断、结果、冲突或明确读者。
- 前几行尽快交代内容是什么、对谁有用、为什么值得继续看。
- 一段只推进一个信息；短段和长段自然交错，不机械切成同样长度。
- 具体事实优先于形容词，证据优先于口号。
- 链接、CTA 和互动只在素材存在且有用时加入。
- 保留用户自己的用词、锋利度和梗；用户样本优先于默认“大黄语感”。

### 5. 做第二遍压缩

删除：

- “最近我在思考”“今天想聊聊”等背景开场。
- 公告腔、课堂腔、公众号总结腔和 AI 式升华。
- 同义反复、假冲突、空泛互动和不必要的标签。
- 为了“一行一句”制造的碎片化断句。

## 输出合同

### 默认改写

\`\`\`md
## 版本 A：{角度}
{完整可发布内容}

## 版本 B：{角度}
{完整可发布内容}

## 版本 C：{角度}
{完整可发布内容}
\`\`\`

直接给成品，不在版本之间插入教学点评。只有用户要求时再解释取舍。

### Thread

\`\`\`md
## Thread
1/
{独立成立的开头帖}

2/
{一个观点、步骤或证据}

...

N/
{具体结论或下一步；有现成链接时再附链接}
\`\`\`

每条都应有局部意义，但不要求脱离整个 Thread 后仍包含全部上下文。

### 诊断

按“有效点 → 最大阻力 → 最值得先改的一处 → 可选改法”输出。只引用能在原稿中指出的证据，不打伪精确分数，不说“必爆”。

## 交付前检查

- 第一屏是否已经出现最有价值的信息？
- 三个版本是否真的是三种打法，而非只换第一句？
- 每个数字、结果、链接和引语是否来自用户素材？
- 是否误把“互动”“链接”“Thread”当成必选项？
- 是否保留了用户原有判断，而不是改成统一的大黄口吻？
- 是否能删掉一句而不损失信息？能就删。
